# Pilot Analysis Template

Use this document as the analysis protocol once baseline/post-assessment, interaction, and feedback data are available.

## 1. Engagement

- Onboarded students = unique Pilot IDs in the roster
- Active students = unique Pilot IDs with at least one valid tutoring interaction
- Returning students = active students with interactions on at least two distinct dates
- Interactions per active student = valid tutoring interactions / active students

## 2. Reliability

Classify each valid tutoring interaction as `Success` or `Error` using the application's logged status.

`Success rate = Success / (Success + Error) × 100`

Report the date range used for the calculation.

## 3. Topic analysis

Assign each legitimate Mathematics question to one primary topic using `TOPIC_CATEGORIES.md`.

Report:

- Number of questions per topic
- Percentage of all legitimate questions per topic
- Most frequently requested topics
- Topics with repeated follow-up questions, if this can be identified reliably

Do not infer that a topic is a learning weakness solely because it has many questions. High volume can also indicate high interest or frequent practice.

## 4. Baseline/post-assessment

For students who have both measurements:

`Improvement = post-test percentage − baseline percentage`

Report:

- Number of matched students
- Mean baseline percentage
- Mean post-test percentage
- Mean improvement in percentage points
- Median improvement, where practical
- Number/percentage of students who improved

Use cautious language. A simple pre/post pilot comparison demonstrates observed change, not causal proof that Robo-Teacher alone produced the change.

## 5. Student feedback

For survey statements 1–7:

- Mean score (1–5)
- Percentage selecting 4 or 5

Summarize open-ended responses by recurring themes, removing identifying details.

## 6. Reporting rule

Only use figures that can be traced to the underlying pilot data. Never substitute targets for actual results, and never invent missing values.
